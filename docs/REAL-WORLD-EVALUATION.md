# 实用任务验收

这份清单用于检验真实模型能否交付可用成果。当前仓库的自动回归证明工作流、存储和样例工程的行为；它们使用模拟模型，不提供实际模型的生成成功率。本轮没有执行下列付费任务，所有案例均为待测。

## 固定条件

同一轮记录模型名、服务商、日期、工作台代码版本、全局模型参数和运行环境。不同模型或参数分别记录；规划、生成和审查仍共用现有全局配置。真实模型调用由操作者自行确认启动，按服务商用量计费；本清单不自动请求模型、不增加累计 Token 配额。

文档案例使用自备的小份资料；工程案例用空白测试数据、固定 React / Express / SQLite 技术栈。在支持的 Linux 隔离环境验证代码，不能在主机直接运行未审查源码。无需实际付款、客户信息或生产服务密钥。

开始前保存原始目标和验收标准；每个案例至少独立执行 3 次，保留所有失败和中断记录。发现遗漏时先按原标准验收，修改目标后的结果单列，不用更宽松的标准替代失败。

## 六个首批场景

1. **个人作品集文案（文档）**：提供 3 个真实项目的目标、工作与结果，交付首页介绍和每个案例正文。验收：三个案例均覆盖资料里的事实，不编造客户、收入或指标；内容可编辑导出；引用能追溯到输入。
2. **一周内容计划（文档）**：提供受众、产品特点、发布渠道和禁止承诺，交付 5 个选题与 2 篇完整正文。验收：选题不重复、正文符合渠道与禁用要求；成果进入相应任务并能人工验收；返工前的版本可找回。
3. **已有资料的对比研究（文档）**：导入三份明确标明来源与日期的资料，再提出跨资料问题。验收：结论引用实际命中的资料，缺失信息明确写为待确认；不同项目私有资料不会混用。此案例不要求联网检索，也不把模型常识当新资料。
4. **个人笔记网站（工程）**：新增、修改、删除和按标题筛选笔记。验收：每条原始要求保留在需求清单；使用随机内容新增，重启后读回，修改和删除生效；刷新及 390px 页面可操作，源码与报告能导出。
5. **带业务校验的预约登记（工程）**：填写姓名、日期和可选备注，同一天只能登记一次。验收：必填校验、重复冲突提示、持久化与跨重启查询均满足；失败请求不写入半条记录。需要专门人工或额外测试检查重复规则，不能仅凭通用持久化检查判定通过。
6. **在稳定工程上继续迭代（工程）**：先验收笔记网站，再添加标签；生成前端阶段中断后重新启动工作台、确认恢复。验收：已完成契约和后端阶段不重复收费调用，稳定源码仍可下载，旧版功能不丢失，新需求有当前源码与验证证据；重新验证不能自动继承人工验收。

## 每次保留的记录

- 原始目标、逐条验收标准、参考资料范围与输入大小。
- 执行版本、开始/结束时间、完成阶段、失败原因和恢复次数。
- 实际模型请求数、返回的 Token 用量；未返回用量写“缺失”。费用采用服务商实际账单或明确标注的估算，不虚构单价。
- 人工介入次数、具体修改及耗时；自动返工次数单独记录。
- 最终交付文件、测试报告、来源版本和逐条人工验收意见。
- 最终结果使用“全部标准通过 / 部分通过 / 失败 / 中断待恢复”，并说明仍未覆盖的要求。

先报告“无需人工改稿即可全部通过”的次数，再报告“人工修订后通过”的次数，两者各自除以实际尝试次数；同时列出耗时与费用范围。少量样本只能帮助决定下一步开发，不作为普遍成功率承诺。

## 后续功能如何排序

- 若重复问题来自安装或环境不明，优先补安装向导与验证环境连接方式。
- 若源码可用但用户无法试用，按交付路线图实现独立源、可靠隔离的交互预览；预览无法隔离时继续禁用。
- 若问题集中在资料检索，先补导入、来源和过期标记，再评估向量/混合检索是否带来实际收益。
- 若同类业务规则反复遗漏，把真实反例沉淀为版本化验收模板；模型调用和审查分工的改变应由对照结果决定。

上线部署、外出访问和多模型分工仍属于后续设计范围，验收结果出来后再决定投入顺序。当前全局模型配置及人工最终验收保持可用。
