## 3.5.0 安装、批量资料与交互预览（待发布）

- **跨平台启动**：Windows CMD 与 Linux/macOS Shell 共用 Node 启动器，首次安装依赖、必要时构建、默认本机；`launch:lan` 选择局域网，`doctor` 只读诊断。处理目录定位、Node 版本、端口、构建更新与脚本换行格式。
- **批量资料导入**：最多 20 个 UTF-8 TXT/Markdown，单文件 200 KB/10万字符、批次 2 MB。确认范围后预览，同正文跳过，同名默认保留，可明确替换或另存；保存前再次校验冲突，不覆盖任务成果镜像。保留原文件名、更新时间与导入时间，旧数据兼容。
- **受控交互预览**：已验证且源码/需求一致的工程可以申请 Linux 隔离会话。可信浏览器输出 PNG，工作台发送有限动作；应用后端再经独立 user/PID/proc/tmp 隔离，不能访问控制器进程或输出通道。10分钟硬时限、90秒无操作回收、单会话、临时数据、停止确认后释放执行锁。
- **回收与界面保护**：启动阶段即注册清理句柄，清理失败保留锁并可重试；前端保留停止失败入口，以请求代次阻止迟到响应复活会话。桌面/手机均有预览控制；不会自动验收或部署。

本轮 Windows 生产构建通过；逻辑/API 共 134 项，130 通过、4 项平台条件跳过、0 失败；浏览器 54/54 通过。还修复了 Windows 临时 HTTP 端口偶发落入 Fetch/Chromium 禁用端口范围的问题，测试 helper 重试可访问端口并有反例回归。Linux 新预览真实回归已加入 CI，但当前电脑没有受支持的 Linux systemd 用户环境，尚无真实通过记录。没有运行真实付费模型质量评测；宣传素材中的界面使用明确标注的演示数据。详细范围见 [安装与导入](INSTALL.md)、[交互预览](INTERACTIVE-PREVIEW.md)。

## 3.4.1 可靠性与环境诊断（待发布）

- **快照容量控制**：新增快照时按最近 50 份和 32 MiB 正文字节双重保留，始终留下最新一份用于回滚；单份超过预算时保留并提示。打开、查询、导出和恢复旧数据均不隐式裁剪历史，当前业务、工程和独立安全备份不参与快照淘汰。
- **容量可见与明确整理**：完整备份区域展示业务、快照、工程、日志和批次占用，区分逻辑容量与档案压缩上限。超额旧快照可在本机预览数量、确认后整理；工作区版本及快照指纹同时校验，执行中或整机恢复中拒绝整理。整理后自动刷新快照列表。
- **工程环境诊断**：设置页和工程面板逐项显示操作系统、Node、隔离工具、用户服务、依赖、浏览器及真实隔离探针结果，并提供处理建议和重新检查。检查不调用模型；并发合并，手动重查最短间隔 5 秒。Windows/macOS 的基础工作台和文档任务可用，自动工程验证仍需受支持的 Linux 环境。
- **Windows 回归适配**：ZIP 用独立 JSZip 解码器检查 CRC、中文文件名和正文，不依赖系统 `unzip`；增加篡改 CRC 反例。POSIX 权限及无权限符号链接分别作为明确的平台子检查处理，不把 Windows 的 `stat.mode` 当作 NTFS ACL 验证。关闭测试服务后等待清理，统一检查临时目录边界并重试文件句柄释放；Playwright 服务使用跨平台环境参数。
- **持续验证**：CI 配置覆盖 Linux / Windows 的构建、逻辑/API、页面回归，并增加独立 Linux 真实沙箱及全部工程页面作业，串行运行且隔离不可用直接失败。CI 环境准备脚本限一次性 GitHub Linux 运行器使用，不用于修改个人电脑安全策略。页脚版本统一从包版本读取。

本轮本机验证：Windows / Node.js 24，生产构建通过，114 项逻辑/API 通过、4 项平台子检查明确跳过、0 失败；49 项浏览器回归通过。真实大资料工作区连续保存 55 次后快照保持在 32 MiB 内，并完成备份导出解码。Linux 新 CI 作业尚待远端执行；没有使用真实付费模型，不代表生成成功率评测。

## 3.4.0 分阶段工程交付

- 新默认流程：接口与数据契约、后端、前端、集成、隔离验证、逐条需求审查；阶段产物持久化，目录边界约束与原子合并，不改变平台脚本。
- 失败或服务中断可确认恢复，只重做未完成阶段；已用次数保留，追加尝试显式确认。停止单条模型调用也停止工程，不擅自重试。
- 原始要求生成验收清单，AI 证据必须引用真实源码和本版实际检查；不让构建通过或模型自评替代人工验收。
- 保留文档模式、旧整包工程、稳定源码基线与只重验功能；完整备份包含阶段草稿，恢复后重新验证、不继承验收或自动花费。
- 手机增加纵向阶段清单、恢复确认、意见与逐条验收；不重做办公室布局。
- 默认模型调用次数较旧整包模式增加；每次启动/恢复前显示范围和费用提示。未新增累计 Token 配额，仍用全局同一套模型配置。

详见 [使用手册](USER-GUIDE.md#分阶段模式34默认) 与 [实现范围](STAGED-DELIVERY.md)。没有引入第三方泄露提示词或任意宿主机工具。

## 3.3.1 复查整改：动态验收与源码基线

- **修复固定样例误通过**：新的 `tests.persistence` 描述业务写入/读回接口和 SQLite 表字段；可信验证器在运行时生成不同的随机值，检查真实业务字段落库、服务重启读回，以及声明的修改/硬删除。浏览器使用另一组随机值，并在重启后的无缓存浏览器上下文检查。空数据库、写死样例、仅浏览器缓存不再能通过这组检查。
- **覆盖范围明确**：修改/硬删除仅在目标支持时声明，省略会显示“未声明，未覆盖”，不会强迫追加不需要的接口。当前动态契约针对一个可新增、读回的文本业务字段，不能替代支付、权限、所有业务规则、软删除或所有字段的逐条验收。表名/接口映射仍由模型声明，这不是任意业务正确性的证明。
- **旧工程不冒充新标准**：旧源码与报告仍可下载，原报告显示旧版检查提示；重验使用新版可信脚本，但缺少动态契约就明确失败。可以基于原源码生成新版本补齐，不会擅自补造验收结论。仅重验不调用模型。
- **源码稳定基线**：新增源码代次和来源记录；重验继承原源码代次，不因检查时间更新而变成新源码。保护最近成功源码基线，并额外保护匹配当前需求的成功版；前后端使用同一推荐规则。旧版来源断链时保守处理，不把重验时间当作源码创建时间。锁定、失败留存和备份恢复兼容。
- **执行与模型策略**：不新增累计 Token 上限或 Token 预算熔断；继续使用全局一套模型配置。现有单次输出参数、超时、人工停止及有限重试不变。分阶段执行、检查点、安全预览等仍按计划后续实施。

## 3.3.0 第一阶段：保护已有成果

完整实施顺序和未完成项见 [交付可靠性计划](DELIVERY-ROADMAP.md)。本版完成第一阶段；分阶段工程执行、断点恢复、逐条验收、安全交互预览、混合 RAG、手机提醒和工程模板仍在后续计划中，不冒充已实现。

- **稳定版与锁定版保护**：普通历史每项目最近 5 版、全局最近 30 版；每项目源码稳定基线、匹配当前需求的成功版、运行中版本以及最多 20 个手动锁定版额外保留，不会被连续失败挤掉。解除锁定时明确提醒可能被清理；备份恢复的历史稳定版也保留，但标注待重验。保留源码会占磁盘空间，仍应下载完整备份。
- **精准需求指纹 v2**：新工程只比较影响实现的项目标题/目标/验收、任务内容/依赖和项目知识。颜色、状态、排序、资料时间戳、重复成果副本和复盘元数据不误报过期；实际需求修改仍失效。旧版指纹没有可靠原始输入时保持严格比较，并在界面提示，不能凭当前内容重置为“不过期”。运行中变更项目状态仍需先停止。
- **完整迁移备份**：设置页新增 `.arkbackup.gz` 下载、预览和确认恢复，包含业务、源码、工程元数据、执行日志、批次和业务快照；原 JSON 按钮改名“导出业务数据”。文件版本与 SHA-256 用于格式/损坏校验，不证明文件来源可信；只恢复自己信任的备份。
- **恢复保护**：仅电脑本机地址可操作；64 MiB 压缩文件、256 MiB 解压上限，超限拒绝而不截断。恢复前检查所有执行已停止、预览后无新修改，先将当前完整备份写入数据目录 `full-backups/` 并刷盘，然后在单一事务内替换数据；失败回滚。恢复前备份不自动清理。模型连接配置和 API Key 不导出/不覆盖，配对会话撤销，任务不自动花费额度。
- **工程恢复不是重新验收**：应用源码与声明用例保留，运行脚本使用本机可信版本重建；历史验证与截图保留为历史字段，但当前验证置空、状态为待重验。外部部署的网站及其数据库不在工作台备份内。新电脑需重新配置模型与隔离环境；超出界面备份容量时使用 SQLite 在线备份工具，不能只拷贝正在写入的单个 `.sqlite` 文件而漏掉 WAL。

## 3.2.1 交付可靠性修复

- **只重跑验证，不必重新生成**：工程环境修复后，点「仅重新验证（不调用 AI）」即可。无需 API Key、0 次模型调用；保留应用源码与声明的测试，更新平台构建/验证脚本，另存一个关联版本，不覆盖原工程。重验不会冒充符合新需求，原版本对应旧需求时仍显示过期。
- **明确选择迭代起点**：默认优先最近验证通过的版本；可以选某一历史版，或明确「从头生成」。启动确认显示起点指纹；版本来自别的项目、已过期删除或仍在执行时拒绝，不悄悄替换。每次生成记录来源版本及源文件指纹。
- **更可信的检查**：沙箱中的源码、声明测试、启动器和验证脚本只读，生成程序不能改写或替换。构建目录/临时数据库按需可写。新增缺失资源 404、无效 JSON 400、手机视口刷新后保留最后一个声明结果的检查；每项报告含实际耗时。下载接口拒绝仍在生成/验证的版本。
- **修复隐藏截断与误导入口**：需求指纹和模型输入不再悄悄截掉任务正文第 5000 字之后的内容；总需求超过 180KB 明确要求拆分，而非遗漏。模型记录区不再把几百 KB 工程 JSON 当 Markdown 交付，提供「查看工程交付」入口；项目底部导出明确标为「导出任务文档」，完整源码请用 ZIP。
- **测试与发布**：补充无 Key 重验、旧需求标记、取消/互斥、历史起点、只读防篡改、手机操作测试；GitHub CI 同时跑构建、逻辑/API 与浏览器测试。真实隔离测试仍为 Linux 专用的显式命令，不会降级到宿主机执行。
