# 交付可靠性实施计划

按依赖分阶段交付；勾选表示代码和回归验证已完成，不代表只有界面或方案。

## 第一阶段：保护已有成果（优先）
- [x] 稳定工程保留：最近成功版与手动锁定版不会被失败记录挤掉；运行中不清理；限额、解除锁定与淘汰规则明确。
- [x] 精准需求指纹：只比较影响实现的语义输入；颜色、排序、状态、复盘不触发过期；旧版本不擅自套用新指纹。
- [x] 完整迁移备份：包含业务、工程、日志、批次与快照；格式版本/校验和/容量限制；本机预览确认恢复；恢复前独立备份；不导出/覆盖模型凭据，不恢复自动花费或已有设备授权。

验收：历史成功版+连续失败仍可下载，元数据编辑不误判而真实需求变更仍过期，换空目录恢复全部数据、损坏备份拒绝且无部分写入，手机不能恢复整机。

本地验证（3.3.0）：生产构建成功；78 项逻辑/API、44 项页面、6 项真实工程页面和 4 项真实隔离测试全部通过。页面覆盖桌面与 390px；测试使用临时数据和模拟模型，不调用用户的模型密钥。真实隔离测试仅代表当前 Linux 环境通过，不等同所有平台或任意业务项目均已验收。

## 第二阶段：交付过程可恢复、可验收
- [ ] 分阶段工程执行：需求与接口契约、前后端实现、集成、测试；阶段产物和费用留痕，仅重做失败阶段。
- [ ] 检查点：重启/网络中断保留有效阶段及草稿；恢复前确认剩余额度，绝不自行重复收费。
- [ ] 逐条验收：需求映射到文件和测试证据；明确未覆盖/失败/待人工，不将构建通过等同全部需求完成。

验收：中途停止、重启后从正确阶段恢复且不超预算；缺少任何需求证据时不能宣称整体验收通过。

## 第三阶段：真正可试用的交付
- [ ] 安全交互预览：操作系统隔离、独立源或受控远程浏览器；不信任生成页面，不与工作台同源；过期回收/可停止/手机操作。
- [ ] 部署中心：运行指引、环境检查、容器构建证据、部署日志；公开部署/绑定域名/密钥输入须另行确认。

验收：实际填表、写库与刷新读回；预览不能访问宿主文件、密钥、网络/工作台 API；无可靠隔离时禁用而非退回宿主执行。

## 第四阶段：知识、手机与复用
- [ ] 项目知识升级：文件导入、增量索引、来源与过期标记；可选向量混合检索并明确费用，关键词模式可独立工作。
- [ ] 手机待办与提醒：完成/失败/审批中心、离线草稿；不自动推送敏感正文。真正外出访问的 VPN/安全隧道另行配置，不裸露公网。
- [ ] 工程流程模板：版本化的工程骨架、验收用例及执行配置，实例化时清除业务数据/凭据/旧验收结论。

## 每阶段发布要求
独立临时数据库和模拟模型测试；构建、逻辑/API、桌面/390px 手机回归；涉及运行生成代码必须增加真实隔离回归。提交 GitHub 前不包含 .local、凭据、数据库、测试截图或备份。未完成项保留清单，不宣称已交付。

## 界面约束
沿用用户认可的办公室界面，不重做导航。使用现有 DM Sans 与灰绿配色（墨色 #292d32、纸白 #ffffff、浅底 #f5f7f8、灰绿 #6d8576、警示色 #ad663b）。工程版本行补充“自动保留/已锁定”与说明；设置页把业务导出和整机迁移清晰分组。左对齐，移动端按钮换行，危险操作独立确认；不增加装饰性图表或假百分比。
