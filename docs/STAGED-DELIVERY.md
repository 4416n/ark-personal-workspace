# 分阶段工程交付实施与验收

## 本轮范围

在既有 React / Express / SQLite 工程与 Linux 隔离验证器上增加可恢复的阶段执行，不引入外部提示词、不开放任意 shell 或宿主机文件权限、不新增累计 Token 配额。旧工程和旧整包 API 保持兼容；新界面默认使用分阶段流程。

阶段：接口与数据契约 → 后端实现 → 前端实现 → 集成与测试声明 → 隔离验证 → 逐条需求审查。

- 每个模型阶段使用独立请求，输出通过格式/路径/范围检查后原子保存为检查点。
- 后端、前端阶段只能更新各自目录；集成与修复按文件更新，不隐式删除未返回文件。平台脚本不可改写。
- 修复阶段不可修改既有测试契约；运行失败和 AI 指出的缺失共用有限修复次数。语义缺失经返工仍存在时保留“缺失/待人工”，不自动通过；需要改变接口/测试时生成新版本。
- 失败和取消保留最近有效产物；重启不自动调用模型。恢复校验工作台版本、需求指纹和检查点版本，明确剩余阶段与额外尝试。
- 自动重试有界、失败尝试与用量留痕；恢复不重置已用计数。用户可以在恢复确认中显式追加有限尝试。
- 需求清单由项目目标、项目验收及任务原文生成，模型不能减少条目。引用必须指向当前源码真实片段和实际检查项。AI 建议、测试证据、人工验收分别记录，缺证据不能冒充已交付。
- 全量迁移保留草稿与阶段记录，但清除当前验证和人工验收结论；运行阶段暂停，需要本机重验和显式恢复。

## 验收

1. 中断前端后恢复，不重做契约和后端；已用次数不清零，前端错误输出不覆盖后端。
2. 需求变化、过期检查点、并发恢复、无确认、无 Key 的模型阶段均拒绝。
3. 失败重试耗尽时停止；显式追加后只重试相应阶段。隔离不可用不循环调用模型。
4. 遗漏需求、虚构文件/测试引用、以测试通过代替业务验收不能获得完整验收结论。
5. 检查点与完整备份往返，恢复后不会偷偷花费或继承验收。
6. 使用临时数据库和模拟模型执行单元/API、桌面/390px 页面测试；真实 Linux 工程验证串行运行。上述测试不是实际模型成功率评测。

## 界面

沿用现有 DM Sans、墨色 #292d32、纸白 #ffffff、浅底 #f5f7f8、灰绿 #6d8576 和警示色 #ad663b。工程台增加左对齐的阶段清单、恢复确认与逐条验收，不重做办公室导航，不增加装饰图表。手机使用纵向列表，按钮换行。
