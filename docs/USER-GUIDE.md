## 安装与启动

环境：Node.js 22.18+（推荐 24+）、npm。

```bash
git clone https://github.com/4416n/ark-personal-workspace.git
cd ark-personal-workspace
npm ci
npm run build
npm start
```

打开 **http://127.0.0.1:5173**。Linux / macOS 也可以在项目目录运行 `bash 启动工作台.sh`；Windows 使用上面的 npm 命令。保持启动终端开启，Ctrl+C 停止。

首次使用可在「工作台设置」修改默认昵称「小舟」，并清除示例项目。升级已有工作台不会覆盖你的个人资料。公开仓库不提供绑定某台电脑路径的桌面快捷方式。

首次升级请使用原来的电脑浏览器与地址，确保迁入你的已有数据。完成迁移后，授权设备共享电脑数据库；浏览器缓存与视图偏好仍按地址独立保存。

## 连接模型

在「工作台设置 → 连接 AI 模型」填写：

| 服务 | Base URL | 模型示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | 使用账户支持的模型 ID |
| 自定义 | 支持 Chat Completions 的接口前缀 | 使用服务商提供的模型 ID |

Base URL 不包含 `/chat/completions`。远程服务使用 HTTPS，本机模型允许 `http://localhost:端口/v1`。模型名称、价格、额度以自己的服务商账户为准。

「保存并测试连接」会真实发送一次简短请求。更换服务地址时，旧 Key 不会自动发给新地址，需要重新填写。

**离线规划是规则模板，不是模型推理。** 普通 AI 员工任务生成文字、方案或代码草稿；只有「工程交付」经确认后会在隔离环境中构建与运行生成的网站，不会部署服务、发送消息或操作外部系统。计划工时用于分工估算，不是 AI 实际运行时长。技能等级和风格标签由你配置，不代表经过评测的客观能力；风格标签用于角色输出指令，技能标签和等级参与分配评分。

## 推荐体验顺序

1. **办公室**：点击部门查看职责与任务，点击员工工位查看工作面板，再按需编辑档案。支持日常 / 负载 / 能力视图、缩放、全屏；手机默认使用可读的部门卡片，可切换空间平面图并横向滑动。
2. **团队**：编辑员工角色、技能等级（1–5）、工作风格、指令与计划容量。可从角色库招募研究、运营、质检、预算伙伴；也可新建部门、导入 JSON 员工名册。暂停接单的员工不参与自动推荐。
3. **目标拆解**：一句话写下目标，补充截止日期、验收标准、计划预算。无密钥可用离线规则规划；连接模型后可智能拆解。
4. **确认分工**：编辑每项任务、比较候选人、调整前置任务；查看超载提醒。匹配分由技能等级与覆盖（75%）及分配后剩余容量（25%）组成，可手动覆盖推荐。
5. **任务看板**：完成前置任务后，点击「生成交付物」。已完成的前置成果会作为后续任务的参考，结果自动保存为待验收。
6. **决策中心**：集中验收、安排未分配任务、处理逾期。退回时必须写明要求；重新生成会带上审批意见和上一版成果。通过后同步更新进度。
7. **经营数据**：查看真实任务完成率、部门工作量、员工容量与计划预算，按任务截止月份筛选并导出简报。预算不是收入，也不是实际支出。
8. **项目复盘**：打开一个项目，切换「项目复盘」，填写经验并保存到知识库，为下一次协作提供参考。

## 文档任务的自动执行

1. **写清交付合同**：拆解计划和任务详情现在分别设置「交付物名称与格式」「验收清单」「完成方式」。流程模板一并保留。旧任务兼容原说明，不会覆盖旧成果。
2. **一键启动**：计划确认页可选「创建并自动执行」；已有项目进入「自动执行」页签。首次必须确认模型费用与范围。无 Key 时只管理计划，不会假装执行。
3. **后台串行推进**：每次一个项目，按前置依赖生成可编辑 Markdown 成果，再用独立请求逐项审查。不通过时按设定最多返工 0–2 次；默认 1 次。可选「AI 审查通过后自动完成任务」或「等待人工验收」。独立可执行任务不因其他人工任务而全部停止。
4. **明确交付**：在交付清单中查看正文、验收证据、引用来源与阻塞原因，一键导出完整 Markdown 交付包。AI 审查记录明确标注 AI，不冒充人工审批。新版本替换成果、修改任务要求或项目验收条件时，旧 AI 审查不再作为本版有效结论。
5. **有界执行**：默认一批最多 30 次调用尝试，可设为 2–100 次；生成、审查和失败尝试都计入，恢复沿用已用次数与返工次数。达到上限、模型失败、审查格式不完整或需要人工操作时停止相应推进。不自动无限重试。整批重新启动会重置计数，必须再次确认。
6. **随时可停**：办公室等页面显示后台状态和暂停入口；关闭浏览器仍执行，电脑服务需保持运行。暂停中止当前模型请求且不启动下一步，已保存成果保留。电脑服务重启后必须手动恢复。更换模型配置只影响新启动/恢复的批次，正在执行的批次使用启动时配置。
7. **数据保护**：执行期间不能直接改动该项目和任务，先暂停；其他项目可编辑。生成期间角色或项目知识改变则不回写旧结果，原输出留在执行日志。实时交付页允许同步，普通编辑表单仍保留编辑保护。备份与执行日志使用数据库插入顺序排序，避免系统时间回拨造成「最新记录」错位；每日独立备份失败也不会将已提交的数据库保存误报失败。

**文档模式边界**：此模式自动执行的是文本 / 代码草稿，不运行代码；网站请使用「工程交付」。工作台不是能操作电脑的通用 Agent，不替你对外部署、发布或完成现实行为。需真实操作的任务应设为「需要人工 / 外部操作」。AI 审查使用同一个已配置模型的独立请求，可能漏判，不等于实测或独立专业认证；项目整体目标仍需你确认，不会自动把项目标记为成功。预计调用上限不是费用预算，费用以服务商账单为准。

## 完整网站工程交付

### 分阶段模式（3.4，默认）

按「接口与数据契约 → 后端 → 前端 → 集成与测试 → 隔离验证 → 逐条需求审查」推进，每阶段输出经检查后保存。前后端阶段只能更新各自目录；集成按文件合并，不隐式删除未返回文件。验证失败的修复不能改变原有测试契约来绕过失败，需改变接口/测试时创建新版本。

- **费用确认**：正常路径 5 次模型请求；选择额外尝试 0 / 1 / 2 时，每个模型阶段相应最多 1 / 2 / 3 次，另保留 0 / 1 / 2 次验证修复，整批最多 5 / 11 / 17 次模型请求。已开始的失败和取消尝试也计入，不是累计 Token 配额。阶段用量仅采用服务商实际返回值，缺报会提示。
- **检查点恢复**：停止、断网或重启后不自动花费；已有合格产物与草稿保留。「从检查点继续」确认剩余范围、已用次数和本阶段追加次数，使用当前全局模型。每次可显式追加 0–2 次，单阶段最多100次累计尝试；不会通过恢复清零。需求变化或检查点过期会拒绝恢复，请基于完整旧源码生成新版本。
- **草稿与工程分开**：未完成集成时可查看阶段源码、锁定重要记录并做完整备份，但不提供冒充完整工程的 ZIP。集成后的源码即使运行检查失败也可下载；只有验证通过才标为“构建与冒烟通过”。普通历史清理仍适用，重要草稿请锁定/备份。
- **逐条验收**：清单保留原始项目目标、项目验收全文、任务范围与各项标准（最多240条，超限拒绝，不截断）。项目长目标不自动拆成若干语义条目，需用户明确标准。AI 必须覆盖所有清单 ID，源码引用须真实存在，测试索引须对应本版实际检查；引用存在不证明业务语义已覆盖，因此 AI 建议与人工通过始终分开。AI 明确指出缺失且还有修复次数时，自动定点返工、重测和重新审查；次数耗尽后保留缺失，不自动批准。运行错误和语义返工共用修复次数。
- **人工确认**：构建通过且阶段结束后，对每项填写验收依据，再确认通过或退回。只有所有条目人工通过才显示本版全部验收完成，不自动结项。原始需求变化时旧结论仅属旧版本；新工程、仅重验与完整迁移恢复不继承当前人工验收结论。退回用于记录要求，不自动触发付费返工。
- **兼容与限制**：仍可切换整包生成模式，旧 API 未指定 workflow 时保持整包逻辑。当前为固定粗粒度阶段，不是任意工具循环或逐文件自主代理；阶段内已响应但格式错误的输出保留在执行日志，未完成的流式内容不承诺恢复。没有安全交互预览或自动部署，真实模型效果需另外试用验证。

详细协议与验证范围见 [分阶段交付说明](STAGED-DELIVERY.md)。下面的次数说明适用于整包兼容模式。

**入口**：新目标选择「完整网站工程」，确认计划后点「创建并交付工程」；已有项目打开「工程交付」。输入网站/前后端等目标会预选工程形式，可手动改回文档。已有数据不会强行迁移，新建软件项目默认打开工程页。软件项目不会误走文档自动执行。

- **真正的文件工程**：固定技术栈 React 19 + Express 5 + Node.js 24 原生 SQLite；生成前端页面、API 与数据库实现，不再把代码藏在 Markdown 里。附带锁定版本的 package.json / lock、构建启动器、测试用例、Dockerfile、Compose 和 DEPLOY.md。
- **自动生成 → 实测 → 修复 → ZIP**：后台调用模型输出文件清单，校验必要文件/路径/大小，再在隔离环境真实构建、启动，执行声明的接口读写、服务重启读回、SQLite 文件检查、浏览器表单交互和 390px 溢出检查。整包兼容模式中，失败日志交回模型修复，最多 0–2 次修复；总计最多 1–3 次模型请求。可选单次输出 8k / 16k / 32k tokens，须模型支持；默认 8k，每次模型请求最多 5 分钟，失败不伪装成功。
- **清晰的交付台**：文件树、只读源码、版本、源码 SHA-256、实际测试项/日志与运行截图，下载包含 verification-report.json 的完整 ZIP。失败但已有有效文件时允许下载，并明确标注未验证通过；没有完整文件不会提供假交付包。截图不是在线站点，不嵌入不可信的同源网页。
- **有连续性**：生成新版本会将选定版本（默认优先匹配当前需求的成功版，否则推荐源码稳定基线）的源码一并交给模型，要求保留已有功能和数据兼容性；不保证模型一定实现正确，仍须验证。项目需求/关联资料改变后旧版本标为过期，不沿用旧验收结论。工程和文档批次互斥，进行中锁定项目要求；关闭页面继续，可从全局状态条停止；重启后保留源码但不会偷偷重新花费额度。
- **工程留存独立于业务 JSON**：文件和报告放在同一个 SQLite 的独立表中，普通历史每项目最近 5 版、全局最近 30 版，稳定/锁定/运行中版本额外保留，不塞进浏览器缓存。工程版本**不包含在普通 JSON 导出、每日 JSON 和业务快照中**。重要版本可锁定并下载 ZIP；整机迁移请用设置页完整备份，超出容量时使用 SQLite 在线备份工具。
- **明确支持范围**：当前是此固定技术栈的网站首版生成器，不是任意语言/任意规模的通用编程 Agent。生成文件最多 60 个、600KB；不自动加第三方依赖、连外部服务、登录账号或上线。支付、真实鉴权、数据迁移、复杂业务等需专门实现与复核；Docker 配置已提供，镜像构建与公开部署不在工作台的验证范围内。

### 隔离验证要求

工作台其他功能仍支持 Windows/macOS；**自动工程运行验证目前需要 Linux、Node.js 24+、bubblewrap、systemd 用户服务、可用的用户命名空间、匹配锁文件的 node_modules 和 Playwright Chromium**。Ubuntu/Debian 可先安装 bubblewrap，再在项目内执行：

```sh
npm ci
npx playwright install chromium
npm run test:sandbox
```

不要为绕过检测而放宽系统安全设置。无隔离能力时只交付未验证源码，**绝不回退到宿主机直接执行生成的代码**。界面会显示环境检测结果。

验证使用无外网的文件系统/网络/PID 命名空间，临时构建目录与数据库，源码、测试、平台脚本、锁定的依赖和浏览器只读挂载；不挂载工作台数据库、密钥或用户主目录。systemd 对整个进程树限制 1GB 内存、192 个进程、120 秒运行时间，结束/取消时清理。它不是恶意代码的形式化安全证明；请及时更新系统，私人可信局域网之外不要暴露工作台服务。

**验证通过的含义**：固定构建与冒烟项、模型声明的测试通过；不代表所有业务需求达标、独立安全审计通过或已经部署。业务测试与接口映射由模型声明，动态数据和固定检查由平台提供；这些检查仍需用户结合具体需求进一步验收。工程成功不会把所有计划任务或项目自动改成完成。下载后先审查代码，优先在无真实密钥的容器/专用环境运行。

## 成果可见性与安全续写

- **成果目录和收尾**：任务列表/看板直接预览正文；项目可查看成果目录、导出总文档或按任务打包的文档 ZIP（支持中文文件名）。文档 ZIP 不是可运行工程，完整前后端源码仍从「工程交付」下载。全部文档任务完成后提示复盘，项目不会自动结项。
- **有界续写**：手动生成前确认费用，文本截断时最多 4 次模型调用、每次输出上限 6000 tokens；自动批次中的续写同样占用总调用额度。记录累计用量，服务商缺报用量会明确提示；达到上限仍不完整时不保存为交付物。段数不是完成百分比。工程 JSON 不使用文本拼接续写。
- **可靠的成果知识**：保存时将已完成任务正文同步为带来源标记的只读知识副本，修改请进入来源任务；重开/删除任务清理副本，不动手写资料。仅浏览、刷新不会写库。副本受知识条数与 100 万字符总量上限约束，完整正文始终保存在任务中；旧数据在下一次保存时同步。检索是关键词和预设近义词扩展，并非向量模型；AI 执行会发送命中片段。
- **保留隔离底线**：Windows/macOS 暂不自动运行生成代码，Node 权限开关和 JavaScript 网络拦截不能替代操作系统沙箱；隔离不可用时只交付未验证源码。

## 成果留存与项目复盘

- **成果版本**：手动保存、AI 重新生成和恢复旧版时留存旧成果。在任务详情的「成果与审批记录」中选择版本、对照当前内容、单独导出。恢复会生成新的待验收版本，点击「保存任务」后生效；恢复前尚未保存的人工稿也会留存。
- **审批记录**：决策中心和任务详情的验收操作记录意见、时间与对应版本。多轮退回不会覆盖旧意见；旧版无时间的审批意见单独保留。列表快捷完成、拖拽和批量完成不计为审批通过。
- **项目复盘**：项目详情新增「项目复盘」，根据当前任务汇总完成情况、成果摘要、未完成事项与留存审批。可填写实际达成、可复用经验、下一步行动，保存笔记、导出 Markdown 或沉淀到知识库。再次沉淀会更新同一篇复盘；知识库保存的是当时快照，后续需手动更新。
- **编辑保护**：模型失败不覆盖原稿，生成期间锁定表单；已完成成果被修改后需重新验收，仍遵守前置与后续任务约束。复盘离开或切换视图前提示未保存修改。详情标题栏固定，长内容也能随时关闭。
- **本地运行**：版本、审批和复盘随 JSON 备份一起保存，兼容旧数据。版本对照与复盘汇总无需 API Key；历史版本不附带在生成请求中。

历史留存有上限：每个任务最多 12 个旧版本且正文合计不超过 16 万字符；全工作台旧版本正文最多 60 万字符。每个任务最多 50 条审批，全工作台最多 2,000 条且意见合计不超过 12 万字符。日常任务更新时按时间清理最早历史，不删除当前成果或最新审批意见；恢复备份时不主动裁剪。初次留存旧成果的时间表示「留存时间」，不伪造原始生成时间。重要记录请定期导出。

## 手机共享、可靠存储与 AI 工作流

- **手机局域网访问**：电脑和手机使用同一份工作台数据。在电脑「工作台设置 → 手机连接」扫描二维码，再输入 8 位一次性连接码。连接码 5 分钟有效，设备会话最多 7 天；电脑可撤销所有设备，服务重启后重新配对。模型密钥只能在电脑本机地址管理。
- **电脑数据库与自动备份**：SQLite WAL 原子写入，版本号防止并发覆盖。每次保存前留快照，保留最近 50 份；每天首次保存另存一份独立 JSON，保留最近 30 个有保存记录的日期。在设置中可预览数量变化、导出或恢复，找回误删内容。恢复前再次留存当前数据。
- **跨设备同步**：约每 2 秒同步；独立字段/记录的修改自动合并，同一字段、版本历史或删除冲突要求选择。编辑表单时暂缓接收远端变化。页面已打开时，断网修改暂存在当前浏览器，重连后同步；未同步时离开页面会提示。浏览器缓存空间不足时明确报错，不能当作离线保存保证。
- **AI 执行记录**：生成成果、智能拆解、对话和连接测试均记录开始/结束时间、模型、状态、错误及服务商返回的 Token 用量。支持取消、查看结果、重试原要求；重试不自动覆盖任务，可确认后保存为待验收。保留最近 100 次，服务重启将未结束记录标记为中断。最多 3 次并发执行；取消仍可能产生服务商已处理部分的费用。不虚构价格或未返回用量。
- **项目知识 RAG**：公共资料与项目资料分域，按中文分词/双字词和 BM25 相关度检索。正文按 900 字符分块、重叠 120 字符，每次最多 6 块、每篇最多 2 块；仅把命中片段发送给模型，并提供 `[资料N]` 引用与原文位置。无匹配时明确资料不足，不强行塞入无关笔记。支持 TXT、Markdown 导入及资料范围检索预览。这是本地关键词 RAG，不是向量语义检索；PDF/OCR、Embedding 与混合检索尚未实现。
- **流程模板**：项目详情「保存为流程模板」，保留任务、前置依赖、技能、负责人、验收要求及相对项目截止日的排期。目标拆解中的模板库可预览新排期并创建项目，暂停/离职员工重新匹配。旧成果、审批、执行状态、实际项目预算和知识资料不会复制；创建后可调整。最多 100 个模板，每个 1–100 项任务。

### 手机连接方法

1. 在电脑运行 `启动工作台.sh` 或 `npm start`，保持电脑开机、服务运行。
2. **先在原来使用的电脑浏览器打开 http://127.0.0.1:5173**。首次会把该浏览器的数据迁入电脑数据库；升级前原文也留存在浏览器，可在自动备份区导出。之后使用电脑上的共享版本。
3. 打开「工作台设置 → 手机连接」，手机连接同一 Wi-Fi，扫描二维码并在浏览器打开。
4. 点击电脑上的「生成连接码」，在手机输入这 8 位数字。手机可查看/编辑任务、笔记、复盘，调用电脑已配置的模型。

手机地址取决于电脑当前局域网 IP，切换网络后请刷新连接区域。扫码只包含访问地址，不包含授权码。当前使用 **HTTP，仅限可信家庭/办公网络**，不是公网部署方案。手机流量、访客 Wi-Fi 隔离、电脑休眠或关机会导致无法连接；虚拟机环境需保证手机能路由到虚拟机地址（如桥接网络）。后续可再接安全远程网络或 HTTPS 服务。

仅电脑使用可运行 `npm run start:local`。不要将此端口转发到公网。

## 日常使用优化

- **行动队列**：按本地规则推荐下一步，支持可推进 / 有阻塞筛选，明确等待前置、员工暂停等原因；暂停或结束的项目不进入建议队列。不会自动调用模型。
- **项目聚焦**：在办公室选择项目，高亮相关部门和工位，队列同步筛选；视图、负载模式与聚焦选择可记住。全局统计仍表示整个公司。
- **员工工作面板**：点工位先看分工、负载与待验收成果，直接进入任务；编辑档案保留在面板中。员工状态来自记录，不代表 AI 在后台运行。
- **协作路线**：项目详情在执行清单 / 协作路线间切换，用连线呈现真实前置关系；无依赖的旧任务按独立任务展示，不擅自新增关系。路线图支持最多 100 个任务，大项目使用清单。
- **依赖编辑**：任务中可调整前置关系、查看前置任务；后续任务自动禁选，保存时再次校验循环。有关联依赖时先解除关系再更换项目。
- **防误操作**：离开未保存任务先确认；全屏打开详情时自动退出全屏，避免弹窗被遮挡。

## 其他能力

- 项目和任务的新增、编辑、搜索、筛选、暂停 / 完成 / 删除与 Markdown 导出。
- 看板拖拽、列表快捷完成均遵守前置依赖。重新打开已完成任务前，需要先退回已启动的后续任务。
- 部门职责、负责人及计划预算维护；员工名册导入先预览、确认后追加，不替换现有员工。
- Markdown 知识笔记，TXT / Markdown 导入导出。
- 结合项目与资料的 AI 决策对话，以及无需模型的本地统计简报。
- 全局搜索（Ctrl/Cmd + K）、操作记录、个人资料设置。
- JSON 全量备份、校验后恢复、清除示例数据。损坏的历史数据保留原文并提供下载恢复出口。
- 兼容旧版 `ark-workspace-v1` 数据，不清空现有项目、员工或密钥。

初始项目、任务和示例交付物均有标识。体验后可在设置中「清除示例」；默认四位 AI 员工会保留，不会凭空生成企业营收或员工绩效数据。

## 数据与隐私

- 业务主数据：`.local/workspace.sqlite`。浏览器 `ark-workspace-v1` 为缓存，`ark-workspace-pending-v3` 暂存未同步修改及合并基线；共享保存状态以页面提示为准。不要在未同步时清除浏览器数据。
- 视图偏好：单独保存在 `ark-office-view-v1`，不改变业务数据，不进入业务备份；无效偏好自动回退默认值。
- API Key：项目内 `.local/ai-config.json`，权限 `0600`，不返回前端、不进入业务备份。
- AI 请求会向你配置的服务发送对应目标、任务、角色指令、审批意见、前置成果、工作台背景及检索命中片段，最多 6 段 × 900 字符；其他项目的专属知识不进入检索参考。执行日志保留当时输入、检索来源与结果用于追溯重试，不包含服务端 API Key。
- JSON 业务导出包含项目、任务、交付合同、AI 审查、知识、版本、审批和模板，不包含工程文件/测试报告/截图、API Key、AI 执行日志或自动批次状态；批次状态另存在 SQLite 中，导入 JSON 不会启动任何自动任务；执行结果可在日志中单独导出。复制数据库作完整备份前请先停止服务，或使用 SQLite 在线备份工具，避免漏掉 WAL 中的内容。
- 默认局域网监听 `0.0.0.0:5173`，校验访问 Host/Origin，手机 API 需 HttpOnly 会话，限制连接码尝试频率；没有公网账号系统或云同步。独立浏览器开发模式可用 `ARK_LEGACY=1`。
