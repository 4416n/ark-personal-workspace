# 安装、启动与资料导入

先安装 **Node.js 22.18 或更新版本**，建议使用 **Node.js 24 LTS**。下载并解压仓库，或用 Git 克隆后进入项目目录。首次安装需要联网下载 npm 依赖；日常打开无需重复安装。

## 一次启动

Windows 双击仓库中的 **启动工作台.cmd**。Linux / macOS 运行：

```bash
bash 启动工作台.sh
```

所有系统也可以运行：

```bash
npm run launch
```

启动器固定使用所在项目目录，依次显示依赖安装、页面构建、服务启动的进度。缺少依赖或锁文件变化时使用 `npm ci`；缺少页面或源码更新时重新构建。后续启动复用现有安装和构建。完成后自动打开 `http://127.0.0.1:5173`，可用 `--no-open` 禁止打开浏览器。

默认仅本机可访问。需要手机协同时，在可信局域网运行 `npm run launch:lan`，然后到「工作台设置 → 手机连接」配对。Windows 命令行也可运行 `启动工作台.cmd --lan`。原有 `npm start` 仍按兼容约定启用局域网；仅本机旧命令是 `npm run start:local`。

保持启动窗口开启；关闭窗口、Ctrl+C 或电脑休眠会中断服务。启动器不会替你配置模型或发送收费请求。首次使用在设置中修改个人信息、连接自己的模型，也可先用示例项目熟悉流程。

## 自检与常见问题

```bash
npm run doctor
```

自检只读取环境，不安装依赖、不修改工作台数据、不调用模型。它检查 Node.js、npm、依赖锁、构建和端口；已安装依赖且使用 Node.js 24+ 时，还会列出工程隔离环境检查结果。基础环境未就绪返回非零退出码；Windows/macOS 不支持工程隔离验证，本身不妨碍基础工作台启动。

- **提示 Node.js 太旧或找不到 npm**：安装包含 npm 的 Node.js LTS 后重新打开终端。
- **端口被占用**：如果方舟已经运行，直接访问现有地址；否则停止占用程序或通过 `PORT` 指定端口。PowerShell 示例：`$env:PORT="5180"`，然后运行 `npm run launch`。
- **依赖安装失败**：检查网络和 npm 源；启动器保留错误并停止，不使用不完整的依赖继续运行。
- **构建失败**：按终端提示修复后重新启动；原工作台数据库不会被重置。
- **工程隔离暂不可用**：Windows/macOS 仍可管理项目、生成文本、生成并导出未验证源码。自动工程验证需要 Linux、Node.js 24+、bubblewrap、systemd 用户服务及 Playwright Chromium，具体缺项见设置中的「工程验证环境」。

## 批量导入项目资料

在「知识空间 → 导入资料」一次选择最多 **20 个 UTF-8 TXT / Markdown 文件**。单文件最多 **200 KB 且不超过 10 万字符**，本批合计不超过 **2 MB**。不接受二进制、无效 UTF-8、空文件或不支持的类型；错误按文件显示，有效文件仍能继续处理。

预览里先选公共知识或一个项目。重复判断只在所选范围内进行：同正文自动跳过；同文件名或标题默认保留现有资料，可选择替换原正文或另存副本。自动同步的任务成果不能被资料导入覆盖。确认前可展开查看正文片段；取消不会写入数据。

确认时会再次核对资料，防止用旧预览覆盖刚修改的笔记。出现冲突时点击「重新核对」，重新选择处理方式。导入保留文件名、原文件更新时间、导入时间和完整正文；文件名只作来源展示，原始文件不会修改。来源信息随业务导出和完整备份保留，旧资料仍可正常读取。

导入过程完全在本机解码并存入工作台，不调用模型。后续 AI 任务检索到的相关片段会发送给你配置的模型服务。文件更新时间是所选文件的元数据，不证明资料内容仍然有效；请自行核对时效。PDF、Word 或扫描件请先转换为可读 UTF-8 文本，本版本未宣称支持 OCR 或 PDF 解析。
